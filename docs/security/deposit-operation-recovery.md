# Burn operation recovery

Persist operation/destination/address before display, input reservations and exact plan before signing, signed Native bytes before broadcast, and signed Solana bytes before submission. A lost response is not authorization to construct another economic transaction. Query the recorded Native TXID/mempool and Solana signature/claim/replay accounts first. Retry identical bytes only when the existing state permits it.

Restart before finality resumes observation. Restart after burn broadcast reobserves that transaction and waits for 12 confirmations. Restart after finalized burn reloads the exact evidence and original destination, then resumes attestation/claim; it never asks the user to deposit again. Completed operations remain retired and cannot reopen economically. Their addresses remain observed for late-deposit exceptions.

A replaced/orphaned pre-final burn cannot authorize mint. A contradiction affecting accepted/finalized evidence pauses new economic work. Read-only observation may continue; restoring chain availability does not clear a critical pause automatically. Review the cause before the private resume command for the selected environment; a TEST resume argument cannot unpause Mainnet. No public admin/resume API exists.

Protected TEST recovery has separate evidence from production portability. Real same-account DPAPI reopen and process-kill-after-finalized-burn tests do not prove a replacement host can decrypt keys. `OFFLINE_RECOVERY_BACKUP = NOT_REQUIRED_BY_TEAM_DECISION`; `RECOVERY_RISK = ACCEPTED_BY_KINGPEPE_TEAM`. No offline copy or server-loss recovery is claimed. Loss of the only usable production signing material may leave confirmed but unburned deposits unavailable for automatic processing/recovery. Cloudflare does not mitigate that risk.

Actual process/Bridge restart, journal reload, RPC reconnect and lost-response recovery remain required under the selected private runtime identity, with no duplicate burn or mint. Windows Service/SCM hosting is not required. Optional snapshot tooling retains its source-bound TEST evidence and recovery pause; it is not an activation prerequisite. No automatic economic repair or full-host snapshot rollback guarantee is provided.
