# Mainnet burn runtime

The existing standard-SPL Mainnet Mint is `4QkWKqTMyPEyEb8RMKv3XrcHJ5jbS7k4uQhXVoirphZW` (8 decimals, initial supply zero, freeze authority None). This document describes deployment support, not an activated production service. Program/config deployment and verification of the actual isolated automatic signer remain prerequisites. The Team removed mandatory Windows Service/SCM hosting and offline recovery provisioning. `OFFLINE_RECOVERY_BACKUP = NOT_REQUIRED_BY_TEAM_DECISION`; `RECOVERY_RISK = ACCEPTED_BY_KINGPEPE_TEAM`. No offline backup or server-loss recovery is claimed; see the [accepted recovery risk and optional tooling](../security/burn-offline-recovery.md).

`burn-mainnet-service.mjs` composes the production Native verifier/observer, two independent attester verifiers, protected burn signer, protected payer, journal, Solana artifact/config verifier and authenticated loopback user API. Native and Solana credentials enter through their dedicated server-side DPAPI stores. No browser request can select either RPC or network.

The protected Mainnet journal adds `mainnetControl`; retained TEST journals keep their original format. `PREPARED` requires an empty paused journal. The local operator can move to `CONTROLLED` only after fresh read-only reconciliation and verification of the actual deployed controlled Solana mode. That transition records exactly one operation, original destination, nonce and exact controlled amount, then issues its unique address. Public operation creation remains closed. Amount/destination changes, another operation, stale accounting or an incorrect program mode fail closed.

`NORMAL` requires the recorded controlled operation to be completed with equal deposit, finalized burn and finalized mint amounts. The actual on-chain active mode and fresh reconciliation must also pass. Production flags are derived from this journal, verified mode and current health; a configuration flag alone cannot enable them. A critical/operator pause survives restart. No launch argument clears a Mainnet pause.

The local operator entrypoint accepts `inspect`, `prepare-controlled`, `enable-normal`, `pause` and `resume-reviewed`. It uses a private configuration file and the isolated runtime identity, with the runtime stopped; existing process leases prevent concurrent writers. Inspection and mode preparation invoke a read-only processing cycle and send no Native or Solana transaction. The normal runtime performs automatic processing only after its persisted admission state allows it. The public API exposes none of these administrative actions.

Deployment scripts must verify exact frozen ELF bytes, actual Mainnet genesis, program ownership/upgrade authority and the existing Mint before configuration initialization. `buildMainnetExistingMintInitializationPlan` initializes only the Transceiver and Bridge config accounts; it contains no Mint creation, metadata creation or SPL minting instruction. A verified existing config must be reused, not initialized again.

`mainnet-program-plan.mjs` prepares initial loader-v3 buffer/write/deploy messages with separate payer and upgrade authority. Read-back inspection skips bytes already written and accepts an existing deployment only when its complete executable, ProgramData, artifact bytes and authority match. It has no upgrade path. The isolated deployment regression exercises interrupted upload, exact deployed bytes, existing-Mint initialization and duplicate-initialization rejection using fresh local TEST identities; it submits no Mainnet transaction.

`prepareMainnetBurnStores` runs under the expected isolated Windows SID, which must differ from the Explorer identity. It imports the retained payer and attester identities, generates the Native burn root inside that identity, and creates protected RPC stores and a fresh empty paused journal. It cannot replace an existing custody directory and performs no RPC, deposit-address issuance or transaction. The parent directory must already be protected for the runtime and authorized administrators. Actual automatic signer execution, independent access-denial tests and process restart require separate runtime evidence; CurrentUser unit tests alone do not certify them. The existing Node entrypoint is an ordinary private process and has no SCM dependency. A verified host must preserve that isolation rather than moving the key into Explorer or a shared interactive-user context.

Before the controlled Native deposit, verify the actual automatic signer, separate Native operational fee inputs, both Solana programs/configs, attesters, Solana operational funds and baseline reconciliation. Neither an offline recovery certificate/copy nor the obsolete SCM proof service is an activation control. Loss of the only usable signing material may leave confirmed but unburned deposits unavailable for automatic processing/recovery; Cloudflare does not mitigate that accepted risk. Deposit and burn finality are each 12 confirmations. Native deposit = finalized burn = Solana mint; operational fees do not reduce the user's amount. Keep the public gateway paused until the controlled operation, supply delta and reconciliation pass. Paused/controlled monitoring may remain available without issuing public deposit addresses.

## Private process hosting

The selected host is a hidden private process under the existing limited Bridge account, separate from Explorer. An administrator starts the host with the account credential protected by DPAPI and an administrator-only ACL. Direct Windows logon and process creation avoid the blocked alternate-user/service launcher. A private noninteractive desktop has an explicit DACL for the runtime, administrators and SYSTEM. The narrowly scoped administrator launch context is discarded after process creation; the worker retains its limited token and does not receive administrator privileges. No service registration, arbitrary signing listener or public launch endpoint is involved.

The actual limited-account TEST process has completed a CurrentUser DPAPI round trip and verified its private owner/DACL. An independent ordinary-user check was denied both directory access and decryption of a copied TEST ciphertext. These checks establish the hosting and storage boundary, not yet production custody or full automatic burn validation. The obsolete SCM proof service is outside this architecture and remains untouched. Actual protected signer operation and restart verification must finish before economic enablement.

Host startup/recovery is an operational action; it does not introduce per-deposit approval. The running private Bridge processes eligible deposits automatically through the existing admission gates. A host restart must reopen the same stores and journal, preserve pauses and query chain state before any ambiguous submission is retried. Loss of the key/profile is the accepted recovery risk, not a reason to regenerate custody and discard obligations.
